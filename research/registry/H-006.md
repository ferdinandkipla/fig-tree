# H-006: Day-of-Week Predicts Outcome for Random Entries

## Prior evidence (recorded before test)
None from this project directly. Per `research/S1_INTERIM_FINDING_5_KILLS.md`'s
committed budget, this is the second of three genuinely distinct
mechanism families to be tested before any "no structure" conclusion
is considered (cross-instrument correlation and momentum/mean-reversion
at alternate horizons remain untested).

General market-structure prior (not project-specific): day-of-week
effects (e.g. "Monday effect," weekend-gap-driven Monday/Friday
asymmetry) are among the most commonly claimed calendar anomalies in
retail trading folklore, making this a reasonable candidate to test
formally rather than leave as an untested assumption embedded in market
commentary.

## The survivorship/pseudoreplication trap (inherited from H-002/H-004/H-005)
Unchanged: pooling 100 seeds inflates apparent sample size without
inflating genuine independent evidence. The seed-to-seed dispersion
check is mandatory here, applied to day-of-week buckets instead of
session or volatility-tercile buckets. This is now the FOURTH
hypothesis using this check (H-002, H-004, H-005, and this one) --
per the FDR ledger's note, it has already caught a false positive in
3 of 5 prior tests and must be treated as load-bearing, not optional.

## Explicit note on data reuse (no new simulation required)
Identical to H-005: this hypothesis is tested ENTIRELY on H-004's
existing signed-null sweep (`research/null_runs_h004/`, 100 seeds x 5
instruments x 1H). `entry_dt` is already present on every trade;
day-of-week is derived from it directly. Zero new backtests required.

## Prediction (the falsifiable form)
At least one day-of-week has a mean expectancy on random entries that
is significantly different from the others, in a DIRECTION consistent
across all five 1H instruments (USDJPY, XAUUSD, GBPJPY, EURUSD, AUDUSD).

Days tested: Monday, Tuesday, Wednesday, Thursday, Friday (FX markets
are closed weekends; Sunday-open/Friday-close edge bars are handled by
whatever day-of-week their entry_dt timestamp falls on -- no special
casing, since MT5's H1 bars are already timestamped in the broker's
server time convention used throughout this project).

## Test design
- Data: TRAIN window only (2019-01-01 -> 2022-01-01), per
  `research/S1_DATA_SPLIT.md`. OOS stays sealed.
- Groups: day-of-week extracted from `entry_dt` (categorical, not
  data-derived bins -- no freeze/verdict phase separation needed, same
  reasoning as H-002/H-004's session buckets, which are also fixed
  categorical definitions rather than TRAIN-derived quantiles).
- Metric: expectancy per day-of-week, per instrument, pooled across
  H-004's existing 100 seeds.
- Significance test: identical permutation-test + seed-dispersion-check
  methodology as H-002/H-004/H-005 (2,000 shuffles, max|day_mean -
  pooled_mean| statistic, seed-to-seed dispersion per day required to
  exceed by the observed effect before counting any low p-value as
  evidence).
- Multiple-comparison correction: per `research/registry/FDR_LEDGER.md`
  and `research/fdr_check.py`, this is hypothesis #6. Adjusted
  threshold at time of registration: p < 0.0083 (re-check at verdict
  time in case the registry has grown further).

## Kill criteria (any one refutes)
- Best/worst day-of-week inconsistent across the five instruments.
- Permutation p-value >= the FDR-adjusted threshold in two or more of
  the five instruments.
- A p-value that clears the adjusted threshold but whose effect size is
  smaller than that instrument's seed-to-seed dispersion.
- Fewer than 30 pooled TRAIN trades in the claimed day-of-week for any
  instrument -> INSUFFICIENT EVIDENCE for that instrument.
- Effect vanishes under cost +50% stress (deferred: only tested if the
  primary claim survives all of the above).

## What I will NOT do
- Report a p-value against the naive 0.05 threshold instead of the
  FDR-adjusted one.
- Report a "significant" result without its accompanying seed-to-seed
  dispersion check.
- Special-case weekend-adjacent bars post-hoc after seeing results.
- Run new simulations -- H-004's existing sweep already has everything
  needed.
- Unseal OOS.
