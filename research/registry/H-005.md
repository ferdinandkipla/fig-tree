# H-005: Volatility Regime Predicts Outcome for Random Entries

## Prior evidence (recorded before test)
None from this project directly -- this is a genuinely new mechanism
class, not a variant of the four prior hypotheses (H-001 pullback
depth, H-002/H-004 session structure, H-003 exit-rule value), all of
which tested entry TIMING or exit-rule structure. Deliberately chosen
per the FDR ledger's guidance to avoid a third test in the
session-structure family and to diversify the mechanism space being
searched, not just the instrument/timeframe combination.

General market-structure prior (not project-specific): volatility
clustering is one of the most replicated empirical regularities in
financial time series (GARCH-family literature broadly). The question
here is narrower and more specific to this platform: does a
matched-frequency RANDOM entry's realized outcome differ systematically
between high- and low-volatility regimes, given the platform's own
fixed ATR-multiple stop/target geometry (`strategies/common.py`:
stop_distance/target_distance both scale with ATR at signal time). If
stop/target sizing already scales with volatility, a null effect here
would suggest the platform's ATR-relative geometry is already
absorbing most of the volatility-regime structure -- itself a
findable, useful result.

## The survivorship/pseudoreplication trap (inherited from H-002/H-004)
Unchanged: pooling 100 seeds inflates apparent sample size without
inflating genuine independent evidence, since every seed redraws WHICH
bars are labeled entries from the SAME underlying, autocorrelated price
series. The seed-to-seed dispersion check (H-002's template, confirmed
again in H-004) is mandatory here, applied to volatility bins instead
of session buckets.

## Explicit note on data reuse (no new simulation required)
This hypothesis is tested ENTIRELY on already-existing data: H-004's
signed null sweep (`research/null_runs_h004/`, 100 seeds x 5 instruments
x 1H, fixed 5% entry density, NOT anchored to `trend_pullback`'s
signal count) already captures `atr_entry` on every trade via
`ENTRY_FEATURES`. Zero new backtests are required -- this is pure
analysis, continuing the near-zero-marginal-cost pattern this project
has followed since M2.

## Prediction (the falsifiable form)
At least one ATR-at-entry tercile (computed per instrument, on
TRAIN-window trades only) has a mean expectancy on random entries that
is significantly different from the other terciles, in a DIRECTION
consistent across all five 1H instruments (USDJPY, XAUUSD, GBPJPY,
EURUSD, AUDUSD) -- e.g., high-volatility entries systematically better
or worse than low-volatility entries, everywhere.

Bounded explicitly (same discipline as H-001's amendment): the claim is
about the three OBSERVED TRAIN terciles for each instrument, not
extrapolated beyond the observed ATR range.

## Test design
- Data: TRAIN window only (2019-01-01 -> 2022-01-01), per
  `research/S1_DATA_SPLIT.md`. OOS stays sealed.
- Bins: `atr_entry` terciles, computed PER INSTRUMENT on TRAIN-window
  pooled null trades (100 seeds), frozen via the SAME freeze-then-verdict
  phase separation pattern as `research/run_h001.py` (`--freeze`
  computes and commits tercile edges; `--verdict` is a separate,
  later invocation that only reads the frozen file). This is mandatory,
  not optional -- it is what makes "resist the temptation to peek"
  enforceable rather than aspirational (per H-001's own template note).
- Metric: expectancy per tercile, per instrument, pooled across the 100
  seeds already computed in H-004's sweep.
- Significance test: same permutation-test + seed-dispersion-check
  methodology as H-002/H-004, applied to volatility terciles instead of
  session buckets (shuffle tercile labels across pooled trades, 2,000
  shuffles, max|tercile_mean - pooled_mean| statistic; ALSO compute
  seed-to-seed dispersion per tercile and require the observed effect
  to exceed it before counting any p < 0.05 result as evidence).
- Multiple-comparison correction: per `research/registry/FDR_LEDGER.md`,
  this is hypothesis #5 in the registry. Apply the BH-adjusted threshold
  from `research/fdr_check.py` (p < 0.01 at time of registration, not
  the naive 0.05) -- run `fdr_check.py` again at verdict time in case
  the registry has grown further since registration.

## Kill criteria (any one refutes)
- Best/worst tercile inconsistent across the five 1H instruments.
- Permutation p-value >= the FDR-adjusted threshold (not 0.05) in two
  or more of the five instruments.
- A p-value that clears the adjusted threshold but whose effect size is
  smaller than that instrument's seed-to-seed dispersion -- same check
  that caught H-002's and H-004's false positives, required here as a
  precondition, not an afterthought.
- Fewer than 30 pooled TRAIN trades in the claimed tercile for any
  instrument -> INSUFFICIENT EVIDENCE for that instrument.
- Effect vanishes under cost +50% stress (deferred: only tested if the
  primary claim survives all of the above).

## What I will NOT do
- Extrapolate the claim beyond the observed TRAIN tercile range.
- Re-bin after seeing verdict-phase results.
- Report a p-value against the naive 0.05 threshold instead of the
  FDR-adjusted one.
- Report a "significant" result without its accompanying seed-to-seed
  dispersion check.
- Run new simulations when H-004's existing null sweep already has the
  needed `atr_entry` data -- if additional instruments/timeframes are
  ever needed beyond H-004's existing coverage, that requires ITS OWN
  registered amendment, not a silent scope expansion.
- Unseal OOS.
